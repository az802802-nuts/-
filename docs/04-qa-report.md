# QAレポート：路地珈琲（Roji Coffee）Webサイト

作成: Bridge株式会社 QA担当
参照元: `docs/01-requirements.md`（要件定義）、`docs/02-design-concept.md`（デザインコンセプト）、`docs/03-copy.md`（掲載コピー・参考）
対象: `site/index.html`、`site/menu.html`、`site/about.html`、`site/css/style.css`、`site/js/main.js`

---

## 1. 要件定義にあるページが全て実装されているか

**Pass**

- `index.html`（トップ）／`menu.html`（メニュー）／`about.html`（こだわり・アクセス）の3ページが要件定義どおりのファイル名で実装されている。
- 全ページ共通でヘッダー（店名ロゴ＋簡易ナビ3項目）とフッター（営業時間・所在地要約、SNSリンク）が設置されている。

## 2. 各ページに要件定義で指定されたコンテンツ要素が含まれているか

**Pass**（下記の軽微な補足あり）

- トップページ：ファーストビュー（店名＋キャッチコピー＋ビジュアル）／お店紹介文／魅力ピックアップ3項目／メニュー抜粋＋「メニューを見る」ボタン／営業時間・アクセス要約＋「こだわり・アクセスを見る」ボタン、すべて実装済み。
- メニューページ：導入文／コーヒー・軽食・スイーツの3セクション（品目・価格）／補足注記、すべて実装済み。
- こだわり・アクセスページ：豆へのこだわり／静かな時間／営業時間（表形式）／アクセス（住所・道順・地図プレースホルダー）／お問い合わせ・SNSリンク、すべて実装済み。
- 補足：メニューページの「補足注記」（`.menu-note`）が独立セクションではなく、スイーツセクションの`<div>`内に同居する形で実装されている。デザインコンセプト4.2では「ページ最下部」に配置する旨のみの指定のため致命的ではないが、独立ブロックとして切り出す方がドキュメントの構成意図により近い。

## 3. コピーライターのテキスト（docs/03-copy.md）がそのまま反映されているか

**Pass**

- title タグ、meta description、ヘッダー／フッターの文言、各ページの見出し・本文・カード文言・メニュー品目と価格・営業時間・アクセス文・お問い合わせ文など、`docs/03-copy.md`の文面と突き合わせた結果、すべて一致していることを確認した。
- フッターの「営業時間／定休日／所在地」は、コピー原稿では全角スペースで位置調整されたプレーンテキストだが、実装では`<dl>`＋CSS Gridで同等の見た目を再現しており、内容面の相違はない（実装上妥当な変換）。

## 4. ナビゲーションリンクが正しく機能しているか（相対パス・ファイル名の整合性）

**Pass**

- ヘッダー・フッターのリンク（`index.html`／`menu.html`／`about.html`）は3ページとも同一の相対パスで統一されており、実ファイルと一致している。
- 各ページのナビゲーションで現在地に`aria-current="page"`が正しく設定されている（トップ＝index、メニュー＝menu、こだわり・アクセス＝about）。
- ページ内アンカー（`#main`のスキップリンク、`#intro`のスクロール誘導）も対応するidが存在し機能する。
- Instagramへの外部リンクは`target="_blank" rel="noopener noreferrer"`が統一して設定されている。

## 5. デザインコンセプトのカラーパレット等がCSSに反映されているか

**一部Fail（軽微）**

- カラーパレット（焙煎ブラウン`#5B4034`、深緑`#3E4A3D`、キャメル`#B08652`、ミルクベージュ`#F5EFE6`、くすみベージュ`#EAE0D1`、本文`#3A2E27`、補足`#8A7B6E`、反転`#FBF7F0`）はCSS変数として全てそのまま定義・使用されており、純白・純黒も使用されていない。
- フォントはNoto Serif JP（見出し）／Noto Sans JP（本文）を指定どおり読み込み・使用。行間1.9、見出しletter-spacing 0.08em、ボタン/ナビのタップ領域44px以上、トランジション0.35sなど、タイポグラフィ・モーション方針も概ね準拠している。
- **指摘**：メニューページ（`menu.html`）のセクション背景の交互切り替えが、デザインコンセプト4.2の指定と1段階ずれている。
  - 仕様：導入文＝ベース／コーヒー＝ベース／軽食＝くすみベージュに変更／スイーツ＝ベースに戻す、という交互パターン。
  - 実装：導入文＝ベース（`.section`）／コーヒー＝`.section--alt`（くすみベージュ）／軽食＝ベース（`.section`）／スイーツ＝`.section--alt`（くすみベージュ）。
  - 見た目としては縞模様になっているが、指定された「コーヒーはベース、軽食で変化、スイーツで戻す」という切り替えのタイミングと異なるため、要件からの逸脱として要修正。

## 6. 基本的なHTMLの構文崩れがないか

**Pass**

- 3ページとも`<!DOCTYPE html>`・`<html lang="ja">`・`<head>`・`<body>`の基本構造が揃っている。
- タグの開閉数を機械的に検証したところ、`section`/`div`/`header`/`footer`/`main`/`ul`/`li`/`nav`/`dl`/`table`/`thead`/`tbody`/`tr`/`figure`のいずれも開始・終了タグの数が一致しており、崩れは見つからなかった。
- 各ページ内のid（`aria-labelledby`の参照先含む）に重複はなく、見出し階層（h1→h2→h3）も概ね妥当。
- Lorem ipsum・TODO・仮テキストの残存なし。

## 7. レスポンシブ対応（メディアクエリの有無など）が考慮されているか

**Pass**

- `768px`・`1024px`のブレークポイントがデザインコンセプトのタブレット／PC定義と一致する形で設定されている。
- ナビゲーションはハンバーガー化されず、3項目が常に横並びで表示される（要件どおり）。
- 魅力ピックアップ・メニュー抜粋カード（PC 3カラム→モバイル1カラム）、こだわりページの左右2カラム（PC→モバイル縦積み）、アクセスセクションの2カラム（PC→モバイル縦積み）が、指定どおりモバイルで1カラムに積み替わる。
- ファーストビューの高さはモバイル62vh（60〜80vhの範囲内）、768px以上で78vh（70〜100vhの範囲内）と、指定レンジに収まっている。
- ボタン・ナビリンクのタップ領域は44px以上を確保。`prefers-reduced-motion`にも配慮されている。

## 総合判定

**要修正**

全体の完成度は高く、要件定義の3ページ構成・コンテンツ要素・コピーの反映・ナビゲーションの整合性・レスポンシブ対応は問題なく実装されている。ただし、デザインコンセプトに明記されたメニューページの背景色切り替え順序に食い違いがあるため、公開前に修正を推奨する。

### 修正すべき点

1. **`menu.html`のセクション背景色の順序を design-concept.md の指定どおりに修正する**
   - 現状：導入文(ベース) → コーヒー(`.section--alt`＝くすみベージュ) → 軽食(ベース) → スイーツ(`.section--alt`＝くすみベージュ)
   - 修正後の期待値：導入文(ベース) → コーヒー(ベース) → 軽食(`.section--alt`＝くすみベージュ) → スイーツ(ベース)
2. （軽微・任意）`menu.html`のH1「MENU」について、デザインコンセプトでは見出しを「MENU（メニュー）」として明示する想定だが、実装では「（メニュー）」部分が`visually-hidden`で視覚的に非表示になっている。アクセシビリティ上は問題ないが、デザイン仕様に厳密に合わせるなら視覚表示も検討すること。
3. （軽微・任意）`menu.html`の補足注記（仕入れ状況に関する一文）を、スイーツセクション内の`<div>`ではなく、ページ最下部の独立したセクションとして切り出すと、デザインコンセプト4.2の構成意図（補足注記を独立要素として扱う）により忠実になる。
